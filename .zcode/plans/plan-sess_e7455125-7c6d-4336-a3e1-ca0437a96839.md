# 融入 ambientcss 设计理念（手写实现，零新依赖）

ambientcss 的核心哲学：**声明一个物理光源，一切明暗（阴影/高光/表面渐变）从它确定性派生**，而不是各自为政的装饰性阴影。当前项目 GL 管线已有同源理念（左上主光、interiorGlow、亮度自适应），但光源参数散落硬编码、没有内容发出的环境光、fallback 阴影偏简单。本次落地三个已选方向，全部在现有 token 体系内手写。

---

## 1. 统一光源 token（架构一致化，视觉不变）

**目标**：把「左上主光」显式化为单一光源，CSS 与 GL 从同一来源派生。

- `src/app/globals.css` `:root` 新增光源 token：
  ```css
  /* 单一物理光源（ambientcss 理念）：一切明暗由此派生 */
  --amb-light-x: -0.66;   /* 指向左上的单位向量 */
  --amb-light-y: -0.75;
  ```
- 用 `calc()` 重写以下阴影的偏移量，使其从 token 派生（当前数值反推，视觉零变化）：
  - `--glass-edge-shadow`（globals.css:35 / :117）
  - `--glass-fallback-shadow`、`--ios-material-shadow`
  - `.glass-floating-ui`、map popup 等的 inset 高光行
- `src/lib/liquid-glass.ts` 导出 `AMBIENT_LIGHT` 常量（同值，供 GL 侧 SSoT）；`liquid-glass-canvas.tsx` 初始化时用 `getComputedStyle` 读取 token 并作为 `u_lightDir` uniform 传入 mainPass；`src/shaders/glass-main.glsl` 把硬编码的 `tlCorner`（:267）改为按 light 方向定位受光角——默认值下结果与现状完全一致。

## 3. 内容环境光（NowPlaying 专辑主色 → 环境光晕）

**「发光体照亮周围」**——当前所有阴影都是中性黑，这是 ambientcss `amb-emit/amb-glow` 理念的缺失项，也是 Apple Music 的做法。

- 新建 `src/lib/palette.ts`：`extractDominantColor(url): Promise<{r,g,b} | null>`
  - 32×32 离屏 canvas 绘制 → 量化分桶 → 按饱和度+频次加权选出主色调（避开近白/近黑）
  - 按URL 内存缓存；`crossOrigin="anonymous"`，NetEase CDN 若 CORS 拒绝导致 canvas 污染则返回 null（优雅降级为现状中性外观，无回归）
- `now-playing-card.tsx`：
  - 外层加 relative wrapper，设置 `--media-ambient-rgb: r,g,b`（切歌时更新）
  - 新增环境光层：绝对定位、负 inset、`radial-gradient(rgb(var(--media-ambient-rgb)) …)` + blur 的柔和光晕，位于卡片后方；用 AnimatePresence + spring 做切歌颜色过渡（遵守「禁止 linear/ease-in-out」约束）
  - 内部微染色：Layer 2 渐变遮罩用 `color-mix` 混入少量环境色；专辑封面自身投影（现在是纯黑 :283）混入环境色——「物体的影子带物体自己的颜色」
- PhotoStack/Weather 是 WebGL GlassCard，光晕会盖在 GL 壳层上，本次不做；palette.ts 设计为通用工具，未来可复用。

## 风险与对策

- **NetEase CDN CORS**：污染则返回 null，保持现状外观，无回归
- **光晕绘制在 canvas 之上**（DOM z-3 > canvas z-2）：物理上读作「玻璃前方泛光」，需低透明度 + 限制扩散半径，实现时截图调参
- **calc() 阴影兼容性**：目标浏览器 Chrome 90+/Safari 15+/Firefox 90+ 均支持，无问题
